# AGENTS.md — rules for working on Toishi

General, distributable, offline, Mac-only (Apple silicon) study app for STEM problem practice.
These rules are fixed. Changing one needs a new decision record in `docs/decisions/`.
`docs/spec.md` and `docs/card-format.md` (when present) describe what to build.
A newer accepted ADR supersedes conflicting spec text until the spec catches up (spec DEV-17):
each ADR lists the spec IDs it amends, the spec is updated within the same milestone, and
briefs name both.

## Layout

| Path | What |
|---|---|
| `core/` | Pure Python domain code: SQLite, FSRS, SymPy checking. **No GUI imports.** |
| `app/` | Desktop shell: `main.py` (entry, `--self-test`, `--health`), `api.py` (JS bridge), `shell.py` (the **only** pywebview importer), `csp_compat.py` |
| `app/web_dist/` | Built web UI (gitignored; `npm --prefix web run build`) |
| `web/` | Svelte 5 + TypeScript + Vite page, KaTeX, MathLive |
| `tests/` | pytest; `tests/ui/` = Playwright page tests (marker `ui`) |
| `scripts/` | `check.sh`, `build.sh`, `spike.sh`, `backup.sh`, git hooks |
| `packaging/` | PyInstaller spec, launchd plist |
| `spike/qt/` | M0 PySide6 + QtWebEngine comparison app. Not shipped, not a dependency of `app/` |
| `content-tools/`, `packs/` | Placeholders: pack building tools, read-only content packs |

## Fixed stack (ADR-0001)

- macOS 14+ on Apple silicon only. Python 3.14 (standard GIL build) managed by uv; never
  `/usr/bin/python3`, never free-threaded. 3.13 only with an ADR saying why.
- Shell: pywebview 6.2.1 (system WKWebView), behind `app/shell.py`. PySide6 6.12 +
  QtWebEngine is the documented fallback and lives only in `spike/qt/`.
- Web UI: Svelte 5 + TypeScript + Vite, built to static files. KaTeX and MathLive (>= 0.111)
  are bundled from npm with their fonts and sounds. **Nothing loads from a CDN.**
- Core: stdlib sqlite3, fsrs (py-fsrs), fsrs-rs-python (fitting, ADR-0013), SymPy + mpmath,
  Lark, platformdirs, zstandard.
- Packaging: PyInstaller onedir `.app`, arm64, ad-hoc signed (`codesign -s -`), built on
  the Mac. Release builds run with pywebview `debug` off (`app.main.debug_enabled`).
- Open source (ADR-0022): a public GitHub repository, code under GPL-3.0-or-later, packs under
  their own licenses. No paid CI: checks run from `scripts/` on the Mac; core tests also run on
  Linux. Never commit personal details (names, schools, courses taken, dates, machine paths).

## Rules

1. **core/ never imports GUI code** (`app`, `webview`, PySide6, PyObjC). import-linter
   enforces it, and only `app/shell.py` may import pywebview.
2. **Offline at runtime (ADR-0002).** The page is served by pywebview's loopback server
   (`http://127.0.0.1:<random port>`), never `file://`, under the CSP in `web/index.html`.
   No remote origins, no `'unsafe-eval'`; `'unsafe-inline'` for styles only (KaTeX/MathLive).
   Tests fail on any outbound request (Python socket tripwire + Playwright request guard).
   Don't call pywebview's `evaluate_js` from our code: it wraps scripts in `eval`.
3. **Nothing typed by the user is evaluated as code (ADR-0003).** No `eval`, `exec`,
   `compile`, `sympify`, `S(...)`, `parse_expr`, `sympy.parsing`, `lambdify` in our code
   (ruff + `tests/test_no_eval.py`). User text goes through our own parser into SymPy objects.
4. **All state lives in SQLite (ADR-0004).** WKWebView keeps no browser storage here
   (private mode; `storage_path` is a no-op on macOS), so no localStorage/IndexedDB.
   Read-only pack DBs + one `user.db` per profile, WAL mode, in
   `~/Library/Application Support/com.toishi.app/`.
5. **Commit every graded answer immediately**, in its own transaction. Cmd+Q can end the
   process without running exit handlers, so never buffer writes until shutdown.
6. **Bridge methods run on pywebview worker threads.** Keep them thread-safe; never share
   one `sqlite3.Connection` across threads. The public methods of `app.api.Api` and the
   `BridgeApi` interface in `web/src/lib/bridge.ts` must match (a test checks).
7. **Every change comes with tests.** `core/` runs under plain pytest with no GUI.
8. **Decision records** (`docs/decisions/NNNN-title.md`) for major choices. Never switch
   toolkit, CDN or eval rules without a new ADR.
9. **Dependencies are pinned**: exact `==` pins in `pyproject.toml` + `uv.lock`; exact
   versions in `web/package.json` + `package-lock.json`. Web assets ship with their
   licenses (`app/web_dist/licenses/THIRD-PARTY-LICENSES.md`, generated by Vite).
10. **Run `./scripts/check.sh` before committing** (`fast` runs as the pre-commit hook;
    `app` on the Mac before anything you'll actually use). Bash scripts use
    `set -euo pipefail`, stay bash-3.2 compatible, and fail clearly off macOS.
11. Never put the live repo in iCloud/Dropbox; `scripts/backup.sh` puts bundles there.
12. **The app is general.** Anyone should be able to study any course in any STEM field (and later
    language skills such as grammar, spelling and reading comprehension). Never hardcode a course,
    school, exam or subject in code: course content comes from packs and imports, and exam details
    (date, length, problem count, calculator policy) come from what the user enters. Math checking
    is one answer-checking module among others, not an assumption of the core.
13. **No AI in the app (ADR-0019).** No model calls of any kind at runtime, local or remote, not
    even optional or bring-your-own-key. AI is a development tool only: it writes code and content
    offline, and its output is verified before it ships.
14. **Correctness before features (ADR-0019).** A defect in grading, scheduling or saved progress
    is fixed, with a test that fails before the fix, before new features ship.
15. **No student-supplied code runs in the core or web process** (spec, STEM seams).

## Environment variables

`TOISHI_DEBUG=1` (Web Inspector, dev runs only) · `TOISHI_DATA_DIR` (data dir override) ·
`TOISHI_BROWSER` (Playwright engine; default webkit on macOS) · `TOISHI_REQUIRE_UI=1`
(missing web build fails instead of skipping) · `TOISHI_BACKUP_DEST` / `TOISHI_BACKUP_KEEP`.
