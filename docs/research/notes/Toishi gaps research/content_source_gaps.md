## 1. Reuse policies for Japanese entrance exams (Osaka, Tohoku, Nagoya, Hokkaido, Science Tokyo, Hitotsubashi, Waseda, Keio, Kobe, Tsukuba, Hiroshima, DNC Common Test)

### Takeaway
Six more sources now have verified policies that permit reuse without asking first: Osaka, Tohoku, Nagoya, Hitotsubashi and Hiroshima (each with attribution, change marking and reporting conditions), plus Tohoku's AO exams under a separate policy. Kobe and Hokkaido publish math problems with official answers, but I found no policy that permits reuse without asking. Reusing these sources would need permission. The DNC (Common Test) and Science Tokyo both need an application before use. Waseda tells users to clear permission themselves. Tsukuba does not post its main written exam (前期) online. I found no undergraduate exam archive on Keio's own site.

### Cited Findings

**Osaka University (no prior approval since March 6, 2024; current terms dated March 28, 2025)**
- The 2024 notice says reuse no longer needs prior approval if the conditions are met. Quote: 「今後は、下記に則すことを条件として、本学の事前承認を得ることなく利用できるよう変更します。」 Using a problem counts as agreeing to the conditions. Quote: 「本学の問題を利用した時点で、利用条件に同意したものとみなします。」 — [Osaka notice 2024-03-06](https://www.osaka-u.ac.jp/ja/admissions/faculty/general/files/s9dfgq/@@download/file)

### Inferences
- **Usable tier (no prior approval, conditions only):** Tokyo, Kyoto, Kyushu and Shinshu (from earlier research), plus Osaka, Tohoku, Nagoya, Hiroshima and Hitotsubashi (verified here). For calculus, the most useful are the science-track (理系) math papers: Tohoku 数学（理系）, Nagoya 数学（理科系）, Osaka 前期 数学（理系）, Hiroshima 前期 数学 for science students, and Hokkaido 数学β (Hokkaido would need permission).
- **Official answers:** Tohoku (in 出題意図, when an answer is unique), Nagoya (正解・解答例), Hokkaido, Kobe, the Science Tokyo 医歯学系, and DNC (multiple-choice answer keys) publish official answers or examples. For the others, any solution the user writes must carry the "unofficial / not published by the university" label.
- **Reporting is triggered by publication.** Every one-month reporting duty above runs from 「成果物の公表」 (Osaka, Tohoku, Hiroshima, Nagoya), and Nagoya's definition of secondary use is publishing or posting online. A private app that is never published or distributed arguably triggers no report. This is my reading, not a ruling from any university. If the user ever shares the app or deck, the report deadlines apply. Caveat: the self-study exemptions in Tohoku, Hiroshima and Nagoya name 受験予定者 (prospective examinees), which the user is not.
- **Translation:** none of these policies mentions translation. Every no-approval policy requires marking changes (改変 / 改題), so an English translation should carry a "translated and adapted (改題)" note next to the attribution.
- **Cheapest-first extraction plan:** (1) For Tohoku, Nagoya, Osaka, Hiroshima and Hitotsubashi, download the math PDFs and any answer PDFs by hand (a handful of files per year). (2) Pick 数学III problems on limits, differentiation and integration. (3) Translate and write a card for each. Attribution template: "Source: [University] [year] [前期/後期] 数学 第n問, translated and adapted (改題) by [user]; solution unofficial unless marked." (4) Keep a provenance table (source URL, retrieval date, policy URL, policy date) in case a report is ever needed. Skip DNC, Science Tokyo, Kobe, Hokkaido, Waseda and Keio unless the user applies for permission.

## 2. The openwebwork renderer (status, running it, API, JSON, failure modes, throughput, GPL) and alternatives

### Takeaway
The renderer is maintained, but `main` has had no commits since June 2025 (`develop` since August 2025). It runs as a locally built Docker image on port 3000 with the OPL mounted. `POST /render-api` with `_format=json` and `isInstructor=1` returns the full PG answer hash, so `correct_ans` and `correct_ans_latex_string` are available for every answer blank. I verified this in the source code. Solutions do not come back as a separate field; they are embedded in `renderedHTML`. Throughput is undocumented, so a pilot is still needed.

### Cited Findings
- **Status:** `main` last commit 2025-06-18 ("Merge pull request #20 … remove-copyright"). `develop` last commit 2025-08-05 (localization update, static-file traversal protection). There is also a `honor-outputformat` branch. PG is pinned as a git submodule at `lib/PG` (commit 4b3e564…). — [openwebwork/renderer](https://github.com/openwebwork/renderer) (git log and `.gitmodules` read from a clone)
- PG upstream is active: version 2.21, last commit 2026-10-27. — [openwebwork/pg](https://github.com/openwebwork/pg) (VERSION file)
- **Running it (README):** clone the OPL into `volumes/`, `git clone --recursive` the renderer, run `docker build --tag renderer:1.0 ./container`, then `docker run … --publish 3000:3000 --mount type=bind,source=…/webwork-open-problem-library/,target=/usr/app/webwork-open-problem-library --env MOJO_MODE=development renderer:1.0`. Non-OPL content can be mounted at `/usr/app/private`. Override config by mounting `/usr/app/render_app.conf`. The README names no prebuilt registry image. — [renderer README](https://github.com/openwebwork/renderer)
- **Dockerfile base:** `FROM ubuntu:20.04`, Node 16 from nodesource, Perl dependencies from apt and cpanm. — [renderer Dockerfile](https://github.com/openwebwork/renderer/blob/main/Dockerfile)
- **Routes:** `/render-api` (main), `/render-ptx` (PreTeXt output), `/health`. In development mode (or with `FULL_APP_INSECURE`) you also get an editor UI at `/`, an OPL browser at `/opl`, and `/render-api/cat` and `/render-api/find` for catalogue and search. — [lib/RenderApp.pm](https://github.com/openwebwork/renderer/blob/main/lib/RenderApp.pm)
- **Config defaults:** `STRICT_JWT => 0`, so no JWT is needed. Hypnotoad (production) defaults: `workers => 10`, `inactivity_timeout => 30`, `requests => 5`. — [render_app.conf.dist](https://github.com/openwebwork/renderer/blob/main/render_app.conf.dist)
- **Request parameters (README):** one of `problemSourceURL` > `problemSource` (raw or base64) > `sourceFilePath` (relative to the OPL `Library/` and `Contrib/`, or `private/`), plus `problemSeed`. Optional: `_format` (`html` or `json`; the parameter is `_format`, not `format`), `outputFormat` (`default`, `static`, `PTX`, `raw`), `displayMode` (`MathJax` or `ptx`), `isInstructor` (default 0), `showHints` (default 1), `showSolutions` (defaults to `isInstructor`), `showCorrectAnswersButton`, `includeTags` (JSON only), `language`. `permissionLevel` is deprecated. — [renderer README](https://github.com/openwebwork/renderer)
- **Solutions:** `showSolutions = isInstructor || showCorrectAnswers || showSolutions`, and `showHints = showSolutions || showHints`. These are passed to `WeBWorK::PG->new`, along with `isInstructor`, `forceScaffoldsOpen` and `processAnswers` (default 1). — [lib/WeBWorK/RenderProblem.pm](https://github.com/openwebwork/renderer/blob/main/lib/WeBWorK/RenderProblem.pm)
- **JSON response:** `jsonResponse()` always returns `renderedHTML`, `debug{perl_warn, pg_warn, debug, internal}`, `problem_result`, `problem_state`, `flags`, `resources{regex, alias, assets}` and `JWT{problem, session, answer}`. **Only when `isInstructor` is true** does it add `answers` (the PG answer hash), `inputs`, and `pgcore{persist, persist_up, pgah}`. With `includeTags` it adds `tags` and `raw_metadata_text`. — [lib/WeBWorK/FormatRenderedProblem.pm](https://github.com/openwebwork/renderer/blob/main/lib/WeBWorK/FormatRenderedProblem.pm)
- **What is in each answer entry:** MathObjects `cmp()` fills the answer hash with `correct_ans`, `correct_ans_latex_string` and `correct_value`. — [pg lib/Value/AnswerChecker.pm](https://github.com/openwebwork/pg/blob/main/lib/Value/AnswerChecker.pm). Legacy evaluators also set `correct_ans` (`num_cmp` sets `correct_ans => $correctVal` and `original_correct_ans`). — [pg macros/answers/PGnumericevaluators.pl](https://github.com/openwebwork/pg/blob/main/macros/answers/PGnumericevaluators.pl)
- **Default numeric tolerance** in MathObjects: `tolerance => 1E-4, tolType => 'relative'`. — [pg lib/Value.pm](https://github.com/openwebwork/pg/blob/main/lib/Value.pm)
- **Macros likely to break or need special handling:** PG ships 34 files in `macros/deprecated` (for example `compoundProblem*.pl`, `PGcomplexmacros.pl`, `unionMacros.pl`, `parserMultiPart.pl`, `BrockPhysicsMacros.pl`). Interactive graphics macros include `AppletObjects.pl`, the `LiveGraphics*.pl` files, `parserGraphTool.pl`, `plotly3D.pl` and `GeoGebra`-style applets, alongside the static image macros `PGgraphmacros.pl`, `plots.pl` and `PGtikz.pl`. — [pg macros/deprecated](https://github.com/openwebwork/pg/tree/main/macros/deprecated); [pg macros/graph](https://github.com/openwebwork/pg/tree/main/macros/graph)
- **Licenses:** the renderer is GPL-3.0. PG is GPL v2-or-later or Artistic License 1.0. OPL content is CC BY-NC-SA 3.0 Unported "unless otherwise indicated"; contributors keep copyright and may choose another OSI license in their top-level directory. — [renderer LICENSE.md](https://github.com/openwebwork/renderer/blob/main/LICENSE.md); [pg LICENSE](https://github.com/openwebwork/pg/blob/main/LICENSE); [OPL_LICENSE](https://github.com/openwebwork/webwork-open-problem-library/blob/main/OPL_LICENSE)
- **OPL size (counted from a blobless clone, HEAD 2026-10-29):** 77,134 `.pg` files: 40,541 in `OpenProblemLibrary/`, 29,624 in `Contrib/`, 6,969 in `Pending/` (the README says users should ignore Pending). — [webwork-open-problem-library](https://github.com/openwebwork/webwork-open-problem-library)
- **Problems tied to commercial textbooks inside the OPL:** `OpenProblemLibrary/WHFreeman` (1,264 files, including `Rogawski_Calculus_Early_Transcendentals_Second_Edition` with 1,071 and `Holt_linear_algebra` with 351), `Wiley` (413, including `setAnton_Section_*`) and `UVA-Stew5e` (773). Problem metadata carries `TitleText`, `AuthorText`, `EditionText`, `Section` and `Problem` tags that link a problem to a textbook exercise (example: a Brock problem tagged `TitleText('University Physics Volume 3')`, `AuthorText('Ling et al')`, `Section('5.3')`, `Problem('001')`). — same repo (file listing and a sample `.pg` file)
- **PreTeXt alternative:** PreTeXt can make static versions of WeBWorK exercises using either a webwork2 server (version 2.19 or later; default `https://webwork-ptx.aimath.org`) or a **local copy of pg** (`@static-processing="local"`, default `@pg-location` `/opt/webwork/pg`). The guide says 「The fastest processing happens if you use local」. — [PreTeXt guide §45.12](https://pretextbook.org/doc/guide/html/publication-file-webwork.html); [PreTeXt guide ch. 39](https://pretextbook.org/doc/guide/html/webwork-processing.html)

### Inferences
- **The earlier claim ("JSON returns correct answers when isInstructor is set") is confirmed** by `jsonResponse()`. Without `isInstructor`, `answers` is missing from the JSON.
- **Solutions:** set `isInstructor=1` (or `showSolutions=1`), then parse the solution block out of `renderedHTML`, where PG renders it inside a solution container. The `/render-ptx` route or `outputFormat=PTX` may give more structured statement, hint and solution blocks than scraping HTML. This route was not piloted.
- **Answers that fail quietly:** problems with custom checkers, `MultiAnswer`, "any of these", or answers that depend on other answers can report a `correct_ans` string that is only one acceptable form. Store `correct_ans_latex_string` for display. Where possible, check answers in the app with symbolic or numeric equivalence at relative tolerance 1E-4, rather than string matching.
- **Problems to exclude automatically:** any file that loads applet, LiveGraphics, graphtool or plotly macros; anything under `Pending/`; anything in the `WHFreeman`, `Wiley` or `UVA-Stew5e` folders; any problem whose metadata `TitleText` or `AuthorText` names a commercial textbook (Stewart, Anton, Rogawski and so on). This follows the user's rule against using copyrighted textbook exercises, even though the OPL license nominally covers these files. Also drop any render whose `debug.pg_warn` or `perl_warn` is non-empty, or whose answer hash is empty. Static image problems (`PGgraphmacros`, `plots.pl`, `PGtikz`) need their image assets fetched from `resources` or `/pg_files/tmp/` while the container is still running.
- **GPL:** the GPL governs copying and distributing the program, not the content it renders. Running GPL software privately at build time and keeping only its output creates no GPL obligation, and since the app is never distributed, nothing triggers distribution duties anyway. This is my reading of how the GPL works; I did not fetch the GNU GPL FAQ in this session. The rendered problem text stays under CC BY-NC-SA 3.0, so keep each file's path, author and institution metadata for attribution.
- **Build risk:** Ubuntu 20.04 and Node 16 are old. The image should still build on Apple Silicon with Docker Desktop (arm64 Ubuntu exists), but nodesource setup scripts for Node 16 may fail now. That would be the first thing to check in a pilot. UNVERIFIED.
- **Cheapest-first plan:** (1) Build the `main` image and render one problem (`Library/Rochester/setMAAtutorial/hello.pg`, seed 1234) with `_format=json&isInstructor=1&outputFormat=static`, and check that `answers.AnSwEr0001.correct_ans` is present. (2) Pick a list of Calculus I candidates by grepping `DBsubject(Calculus - single variable)` in the metadata, minus the exclusion list above. (3) Render N seeds per problem with a small client that sends a few requests in parallel. (4) Keep only renders with no warnings and a full answer set. Fallback if the renderer image will not build: PreTeXt with local pg static processing.

### Gaps
- Throughput (renders per second) is undocumented anywhere I looked. Needs a pilot.
- The share of OPL calculus problems that are MathObjects vs legacy, and the real failure rate. Not measured.
- Whether `outputFormat=PTX` or `/render-ptx` reliably separates solutions. Not piloted.
- Whether the Docker build succeeds today on macOS/arm64. UNVERIFIED.

## 3. Open Calculus I problem sources with answers, at exam level or harder

### Takeaway
The CLP-1 problem book is the best verified match: CC BY-NC-SA 4.0, 550 pages, with hints, answers and full solutions for every problem. Its starred problems come from real UBC first-year calculus quizzes and exams. MIT OCW 18.01 (CC BY-NC-SA 4.0) adds real exams, practice exams and solutions. APEX (CC BY-NC 4.0) and Active Calculus (CC BY-SA) are usable textbooks with exercises. The UBC Math Exam Resources wiki has past exams with worked solutions, but its license statements contradict each other and the exam questions themselves are not clearly licensed.

### Cited Findings
- **CLP-1 problem book:** 「Copyright © 2016–2024 Joel Feldman, Andrew Rechnitzer and Elyse Yeager. ## 4. Open problem sources for calculus-based Physics I/II and General Chemistry I

### Takeaway
For physics: MIT OCW 8.01 variants with exams, practice exams and solutions (CC BY-NC-SA 4.0); Crowell's calculus-based *Simple Nature* and the *Problems in Introductory Physics* collection (CC BY-SA, with an answer checker and solutions); and OPL physics in `Contrib/` (Douglas College Particle Dynamics 929 and Statics 818; Brock problems mostly based on OpenStax College Physics). ## 5. Calculator policy and units/angle conventions in the sources

### Takeaway
Only some sources mark calculator use explicitly. OpenStax uses "[T]" for technology exercises. CLP says so in the problem text. Japanese exams are effectively no-calculator, since calculators are not on the list of allowed desk items. WeBWorK evaluates trig in radians by default and needs `Context("TrigDegrees")` for degrees. CLP writes log x to mean ln x.

### Cited Findings
- **OpenStax:** 「Many exercises are marked with a [T] to indicate they are suitable for solution by technology, including calculators or Computer Algebra Systems (CAS).」 — [OpenStax Calculus Vol. 1 preface (Lumen mirror)](https://courses.lumenlearning.com/suny-openstax-calculus1/front-matter/preface/)
- **CLP-1:** calculator use is stated per problem, for example 「You may use a calculator, but only to add, subtract, …」. Angular rates are given in radians (for example "How fast (in radians per second)…"). 「in these notes, we use log x to mean log_e x, which is also commonly written elsewhere as ln x.」 — [CLP-1 problem book PDF](https://personal.math.ubc.ca/~CLP/CLP1/clp_1_dc_problems.pdf)
- **WeBWorK/PG:** 「By default, webwork problems evaluate trigonometric functions in radians. Problems which evaluate trigonometric functions in degrees should alert the student in their text.」 (`contextTrigDegrees.pl`). The default numeric tolerance is relative 1E-4. — [pg contextTrigDegrees.pl](https://github.com/openwebwork/pg/blob/main/macros/contexts/contextTrigDegrees.pl); [pg lib/Value.pm](https://github.com/openwebwork/pg/blob/main/lib/Value.pm)
- **Common Test:** an official exam-site instruction sheet (R8, 鹿屋体育大学試験場) lists the only items allowed on the desk: 黒鉛筆, 鉛筆キャップ, a mechanical pencil for notes, a plastic eraser, a pencil sharpener, a watch, glasses, a handkerchief, tissues and eye drops. Electronic devices must be switched off and stowed. No calculator is listed. — [R8 共通テスト 受験上の注意 (exam-site PDF)](https://www.nifs-k.ac.jp/wp-content/uploads/2026/01/03_R8_%E5%85%B1%E9%80%9A%E3%83%86%E3%82%B9%E3%83%88_%E5%8F%97%E9%A8%93%E4%B8%8A%E3%81%AE%E6%B3%A8%E6%84%8F.pdf)

### Inferences
- **Tagging rule for the app:** set `calculator = required` for OpenStax "[T]" items, `allowed-limited` when CLP's text says so, and `no-calculator` by default for CLP starred, MIT exam and all Japanese exam problems. For OPL problems, the answer box accepts expressions (for example `sqrt(2)/3`), so a calculator is optional unless the problem asks for a decimal.
- **Angles:** default to radians everywhere. Flag OPL problems that load `contextTrigDegrees.pl`, or whose text says "degrees", as degree problems. Show "log means ln" on CLP cards.
- **Units:** treat OPL problems using the `NumberWithUnits` or `FormulaWithUnits` parsers as unit-bearing answers. The app's checker needs unit parsing, or should strip units to a fixed SI unit given in the prompt.

### Gaps
- I found no DNC primary page that bans calculators by name; the evidence is the official allowed-items list at an exam site.
- How APEX, Active Calculus, Light and Matter and the MIT exams mark calculator use was not checked.
- Individual university secondary exams' calculator rules were not checked (they are generally no-calculator, but that is UNVERIFIED here).
